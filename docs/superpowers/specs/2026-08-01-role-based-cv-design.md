# Дизайн: CV под роль вместо одного файла на всё

- **Дата:** 2026-08-01
- **Статус:** утверждён (brainstorming), готов к плану
- **Область:** `sender/` (конфиг, выбор CV, классификация роли, промпт), содержимое `sender/cv/`
- **Связано:** `2026-06-20-ai-relevance-search-design.md` (тот же приём: дешёвая модель
  читает вакансию и возвращает JSON), `2026-06-13-multi-platform-outreach-design.md`

## 1. Проблема

Один PDF `Bolatbek_Yermekov(FD).pdf` уходит на все роли сразу: AI Engineer, Backend на трёх
языках, Frontend, React Native, QA. Заголовок в нём один на всех
(*«Full-Stack Software Engineer with backend-heavy experience»*), имя файла тоже
(`(FD)` прилетает и на вакансию AI Engineer).

Это не гипотеза. Ниже замеры по живому листу и по самому PDF.

## 2. Разведка (2026-08-01)

### 2.1. Что модель реально написала по ролям

Выгружен лист: 201 строка, **101 письмо с текстом**. Роль определялась по тексту вакансии,
из каждого письма извлекалась строка «Мой стек».

| Роль | Писем | Чем открывается «Мой стек» |
|---|---|---|
| **AI / LLM** | 27 | TypeScript 15 из 21 |
| Backend | 19 | Go 8 из 16 |
| **QA** | 18 | вразнобой: TypeScript 6, REST API 4, Jest 1, «уверенный пользователь ПК» 1 |
| Frontend | 14 | React 10 из 12 |
| Fullstack | 10 | TypeScript 3, React 3, JavaScript 2 |
| не определилась | 9 | — |
| Mobile | 4 | React Native 3 из 4 |

Три вывода:

1. **Правило «стек под роль» работает** там, где роль однозначная: Frontend открывается
   React в 10 случаях из 12, Mobile — React Native в 3 из 4.
2. **Самая большая корзина подана хуже всех.** AI это 27 писем, больше чем Backend, и в 15
   случаях из 21 письмо на AI-вакансию открывается словом *TypeScript*. LangChain
   упоминается в 16 письмах из 27.
3. **Строка стека это свалка.** В среднем **15,8–18,0 технологий**, причём почти одинаковых
   во всех ролях: Redis в 21 из 27 AI-писем, PostgreSQL в 16 из 18 QA-писем, Docker и
   GitHub Actions почти везде. Модель не выбирает, а вываливает всё, что видит в CV.

### 2.2. Чего в CV нет вообще

```
Python      0        pytest      0        Kubernetes  0
FastAPI     0        Playwright  0        Selenium    0
Django      0        Jest        0        QA          1  (внутри слова "quality")
```

**AI + QA это 45 писем из 101, почти половина потока.** Под QA в CV нет ничего, кроме k6 в
GGNetworks. Под AI опыт есть и сильный, но слова `Python` в CV нет ни разу, а вакансии
AI Engineer почти все на Python.

## 3. Решение

### 3.1. Восемь ролей

```python
ROLES = ("ai", "backend-node", "backend-go", "backend-python",
         "frontend", "mobile", "qa", "fullstack")
DEFAULT_ROLE = "fullstack"
```

`fullstack` служит двум целям сразу: это отдельное CV для честно-фуллстековых вакансий и
это запасной вариант для всего, что не опознали.

CTO не заводим: в `sender/search_profile.txt` стоит «Intern / Junior / Middle. НЕ
senior/lead/staff», такие вакансии в поток не попадают. Подварианты Fullstack
(Go+Frontend, Node+Python, Python+Frontend) отложены: 10 писем из 101 не оправдывают три
файла, которые придётся синхронизировать при каждой правке опыта.

### 3.2. Структура на диске

```
sender/cv/
├── ai/              cv.tex → Bolatbek_Yermekov_AI_Engineer.pdf
├── backend-node/    cv.tex → Bolatbek_Yermekov_Backend_NodeJS.pdf
├── backend-go/      cv.tex → Bolatbek_Yermekov_Backend_Go.pdf
├── backend-python/  cv.tex → Bolatbek_Yermekov_Backend_Python.pdf
├── frontend/        cv.tex → Bolatbek_Yermekov_Frontend.pdf
├── mobile/          cv.tex → Bolatbek_Yermekov_React_Native.pdf
├── qa/              cv.tex → Bolatbek_Yermekov_QA_Engineer.pdf
└── fullstack/       cv.tex → Bolatbek_Yermekov_Fullstack.pdf
```

Имя папки — ключ роли. Имя PDF видит рекрутёр, поэтому оно называет роль. Исходник лежит
рядом с результатом и тоже не коммитится: в `.tex` телефон и почта, репозиторий публичный.

### 3.3. Поток выбора

```
лид → текст вакансии → LLM-классификатор (OPENAI_MODEL_CHEAP, response_format=json_object)
                              ↓
                        роль из закрытого списка
                              ↓
                CvLibrary: текст CV для промпта + путь к PDF
                              ↓
                     письмо + вложение уходят вместе
```

Классификация обязана идти **до** генерации письма: текст CV попадает в промпт. Это
отдельный дешёвый вызов на лид, по образцу `OpenAIRelevanceScorer`.

Классификатор получает список ролей с коротким описанием каждой и выбирает по смыслу
вакансии, а не по совпадению слов. Регулярка на 101 письме не смогла определить роль в 9
случаях — это и есть причина, по которой выбран LLM.

### 3.4. Компоненты

| Файл | Ответственность |
|---|---|
| `app/domain/cv_role.py` | `ROLES`, `DEFAULT_ROLE`, описания ролей для промпта. Единственный источник правды |
| `app/application/classify_role.py` | ответ модели → валидная роль; всё прочее → `DEFAULT_ROLE`. Ошибки **возвращаются**, не бросаются |
| `app/application/cv_library.py` | роль → `CvVariant(role, text, pdf_path)`, ленивая загрузка с кэшем, цепочка откатов |
| `app/infrastructure/openai_client.py` | `OpenAIRoleClassifier` на `OPENAI_MODEL_CHEAP` |
| `app/config.py` | `cv_path_for(role)` рядом с существующим `CV_PATH` |
| `app/interface/cli.py` | в цикле: классифицировать → взять вариант → генератор из кэша по роли. Выбранная роль и имя PDF печатаются рядом с вакансией, до подтверждения в ручном режиме |

`GenerateMessage` не меняется. Он держит `cv_text` в конструкторе, поэтому в CLI будет
словарь «роль → экземпляр», заполняемый лениво. Ноль правок в классе и ни одного
сломанного теста.

### 3.5. Откаты — ни один не теряет лид

```
классификатор упал или сеть легла   → fullstack
роль не из списка                   → fullstack + предупреждение в лог
папки роли нет или она пустая       → fullstack
fullstack тоже нет                  → первый файл в cv/ (сегодняшнее поведение)
```

Худшая ветка равна тому, что происходит сегодня. Регресса нет нигде.

## 4. Содержание восьми CV

Один и тот же опыт, разный порядок и разный акцент. Ничего выдуманного: всё из раздела 2.3
и из текущего CV.

| Папка | Заголовок | Что ведёт |
|---|---|---|
| `ai` | AI Engineer | Python, LangGraph, LangChain, RAG, 10+ агентских флоу в проде, Meta Cloud API |
| `backend-node` | Backend Engineer (Node.js) | NestJS + Prisma + PostgreSQL, Express + Mongoose + MongoDB, BullMQ, Redis |
| `backend-go` | Backend Engineer (Go) | Gin, GORM, gRPC и цифры GGNetworks: p95 420→160 мс, 550→1700 rps, 5xx 1.8%→0.4% |
| `backend-python` | Backend Engineer (Python) | FastAPI, SQLAlchemy, Alembic, PostgreSQL; AI-работа как доказательство Python в проде |
| `frontend` | Frontend Engineer | React, Next.js, Vue, Vite, TypeScript, Zustand, Zod, TanStack Query, i18n, Tailwind, ShadCN |
| `mobile` | React Native Engineer | React Native, Expo, публикация в App Store и Google Play, TIL как флагман |
| `qa` | QA Engineer | Playwright на 5 площадках, pytest 752 теста, Jest, k6, Postman, Swagger, Jira, DevTools, e2e и интеграционные |
| `fullstack` | Software Engineer | сегодняшний плюс всё выпавшее: GORM, Zod, Zustand, i18n, Vite, Prisma, Mongoose, Expo, Python |

Порядок секций во всех версиях остаётся ATS-совместимым: одна колонка, обычный текст,
контакты → summary → skills → experience → projects → education. Навыки по категориям.

## 5. Правило стека в промпте

Замеренная проблема из 2.1: 15,8–18,0 технологий в строке «Мой стек». Правило живёт в двух
местах и должно поменяться в обоих:

- `sender/profile.md`, пункт 3 раздела «Структура сообщения»
- `sender/app/infrastructure/openai_client.py`, `_SYSTEM`

Новое ограничение: **главная строка не более 7 технологий**, хвост «плюс к пониманию
системы целиком» **не более 4**. Порядок остаётся прежним (релевантное роли первым).

Отдельно: разделение CV по ролям чинит эту же проблему с другой стороны. В Go-версии CV
физически нет ни Tailwind, ни ShadCN, чтобы модель могла их вписать.

## 6. Сборка PDF

Исходник приходит с Overleaf, из него делается восемь версий. Локально ставится
`tectonic` (один бинарник, без установки всего TeX Live) — он собирает все восемь и
позволяет проверить главное: **каждое CV должно остаться на одной странице**. С добавлением
Expo, Prisma, GORM, Python и QA-секции это перестаёт быть само собой разумеющимся.

## 7. Тестирование

| Что | Как |
|---|---|
| `classify_role` | валидная роль проходит; мусор → `fullstack`; исключение → `fullstack`; регистр и пробелы нормализуются |
| `cv_library` | находит файл в папке роли; пустая папка → откат; отсутствующая папка → откат; повторный вызов не перечитывает файл с диска |
| `config.cv_path_for` | подпапка найдена; отсутствие всех папок даёт сегодняшнее поведение |
| Проводка в CLI | генератор и вложение соответствуют выбранной роли (по одному лиду на роль) |

Отдельно от тестов, при сборке: каждый `.tex` компилируется `tectonic` и полученный PDF
занимает **ровно одну страницу**. Это проверка артефакта, а не поведения кода.

Тесты на текст промпта не пишутся: это не поведение, а формулировка. Проверка ограничения
стека — живая генерация на вакансии из каждой роли после правки.

## 8. Границы

Не делаем:

- изменения листа и `COLUMNS` — колонки «Роль» не будет, роль нигде не хранится
- `intake-bot` не участвует вообще
- CV не генерируется на лету: каждый вариант это заранее собранный файл
- не выдумывается опыт, которого нет; всё содержимое CV из раздела 2.3 и текущего файла

## 9. Риски

| Риск | Что делаем |
|---|---|
| Классификатор ошибся ролью | Худший случай = сегодняшнее поведение. В ручном режиме роль печатается перед подтверждением |
| Ещё один вызов OpenAI на лид | Модель дешёвая, ответ короткий. Сбой откатывается на `fullstack`, прогон не падает |
| CV перестало влезать в страницу | Проверяется при сборке, до отправки |
| Восемь файлов разъезжаются при правке опыта | Общая часть (контакты, образование, места работы и даты) одинакова во всех `.tex`; расходятся только summary, порядок навыков и акценты в буллетах |
